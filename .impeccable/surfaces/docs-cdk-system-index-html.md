# CDK access and administration extension

Mode: Operate. Scope: an interactive design prototype at docs/cdk-system/index.html and an implementation specification; no production authentication, billing, account operation or network integration is delivered by this artifact.

Audience: operators entering their own account workspace and administrators issuing import credits and investigating failed access. The user approved joint identity by CDK and email, one-time import charging, merging only never-consumed source keys, per-CDK Sub2API configuration, failure alerts and IP bans.

This is an extension of the established toSub2 workbench. Its existing navigation, graphite and blue system, local UI font stack and responsive table conventions remain authoritative. Composition and behavior follow the approved business brief; no new visual identity or concept tournament is required.

## Direction contract

THESIS: Let people see the consequence of importing, merging or blocking before they commit. Tables and action-specific balance previews carry the information instead of a dashboard of decorative cards.

OWN-WORLD: Inherit the white surfaces, cool gray ground, graphite text and workbench blue of DESIGN.md. Use the incumbent UI font stack, tabular numerals, quiet status text, 8px controls and flat divided tables.

STORY: A visitor validates a CDK, works only on its accounts, previews the import debit and can merge an untouched key. Administrators issue credits, inspect the ledger and respond to suspicious access.

FIRST VIEWPORT: A slim clearly external preview bar precedes the 176px workbench sidebar. The administration view leads with its title and Generate CDK action, a continuous accounting summary, filters and an eight-row CDK table. The signature interaction is a live before/add/after balance equation in import, top-up and merge confirmations. Mobile stacks the navigation and preserves the primary action and row detail entry.

FORM: Established workbench extension, code-led implementation. No random concept assignment applies to this narrowly specified extension. Seed reference: not applicable, existing world and approved business flow.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

Validation: desktop, mobile, dark theme, keyboard dialogs, zero balance, used-key rejection, merged-key invalidation, independent same-email fixtures and security-log to IP-ban flows. All accounts, CDKs, endpoints and IP addresses are synthetic. Preserve incumbent DESIGN.md and .impeccable/design.json; document extension evidence separately.
