# 工作区 SQLite 持久化

授权任务状态、OAuth 结果、登录检查点、账号会话、额度快照、MFA 工作区、换绑状态和账号凭据统一写入运行目录 `.cdk/cdk.sqlite` 的 `workspace_documents` 表。每条记录以 `(cdk_id, name)` 定位，`name` 是工作区内的逻辑路径。账号归属仍采用 `(cdk_id, normalized_email)`；同邮箱在不同 CDK 的凭据与任务保持隔离。

`workspace-storage.mjs` 适配现有读写接口，逻辑路径不代表对应磁盘文件仍然是数据源。授权/MFA/换绑协议子进程通过私有 IPC 请求父进程读写数据库，不获得应用加密主密钥。临时写入在内存中准备，完成后提交 SQLite；数据库已有相同内容时跳过写入。

CDK、额度、账单、安全事件及短信池继续使用原 SQLite 表；优惠检测继续使用每个工作区已有的 `offers/offers.sqlite`。系统加密主密钥仍保存在 DPAPI/Keychain，或由 `TOSUB2_ENCRYPTION_KEY` 提供。

启动时只解锁一次应用主密钥以读取加密元数据；这与逐账号加载密码、MFA 和代理凭据分开。

## 旧数据迁移

首次启动逐个读取旧文件，在一个事务中写入加密记录和工作区迁移标记。失败时不提交迁移标记，可在修复原因后重试。迁移保留旧文件；之后所有业务读写以数据库为准，不再从旧文件重新导入，删除的记录也不会被旧备份复活。

启动恢复只读取任务元数据及记录目录，不读取或解密账号密码、MFA、代理、OAuth 结果、会话或登录检查点。列表使用元数据中的凭据存在标记、结果可用性和额度快照。首次升级会一次性建立旧任务的元数据索引，之后重启直接查库；索引过程不会解密 DPAPI 凭据。

Windows 旧 DPAPI 凭据按密文原样迁入 SQLite，不在启动时批量转换。首次执行某个账号的重试、导出、配置更新等操作时，才读取并解密该账号的凭据，同时转换为应用加密记录；其他账号不受影响。仅加入授权队列不会加载凭据，等待执行槽位后才加载；显式更新配置或恢复即将清除的中断结果会在执行这些操作时加载。同账号并发操作共享正在进行的加载，系统凭据辅助进程并发限制为 4。缺失资料在执行前校验，避免未加载被误判为不存在，或静默丢失已保存的密码、MFA 和代理。

添加密码和启用 MFA 的中断结果保留到显式账号操作时再恢复。MFA 工作区启动只恢复状态；已生效的 MFA 检查点在用户重试时本地完成保存，避免重复修改远端 MFA。邮箱换绑的账号快照单独加密，启动和列表不打开快照，执行具体换绑或同步操作时才解密。

新凭据、所有工作区持久记录均使用现有 AES-256-GCM vault 加密；关联数据包含 CDK 和逻辑记录标识。凭据本身也保留独立 vault 封装。

本次升级需要重启控制台才会执行迁移。回退前应先停止服务，保存当前数据库和密钥；旧文件只是迁移前快照，不包含升级后新增或修改的数据，不能直接作为最新状态回退。

## 验证

`npm run check:storage` 覆盖旧文件导入、数据库唯一数据源、加密、重复写入跳过、事务回滚、跨 CDK 隔离、协议子进程 IPC 和删除后重启不复活。558 条任务的懒加载集成测试直接统计凭据读取、解密及辅助进程启动，要求启动、列表与再次重启均为零；并验证单账号操作、同账号并发、旧 DPAPI、代理更新、缺失凭据，以及 MFA/换绑快照的延迟恢复。其余授权、MFA、换绑、短信池和 CDK 回归继续验证原业务语义。
