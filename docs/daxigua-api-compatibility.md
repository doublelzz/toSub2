# 大西瓜接码 API 兼容性核对

核对日期：2026-11-19（Asia/Shanghai）。来源：[官方 API 文档](https://tibosb.site/api/docs/)，同时用禁用缓存的请求读取公开页面。当前公开文档仍标为 v1；已使用的鉴权、服务查询、创建订单、查询短信和取消接口未发现必须迁移的字段变化。未用真实 API Key 查询账户或购买号码。

| 对接项 | 当前文档约定 | 本项目处理 |
| --- | --- | --- |
| 接口与鉴权 | `/api/v1`，Bearer API Key，JSON 响应 | 保持当前地址及鉴权，测试可通过 `DAXIGUA_SMS_API_BASE` 覆盖 |
| 服务 | `GET /services` 返回 `country`、`project` 和 `uses` | 实时选择服务；次数不计作金额 |
| 创建 | `POST /orders`，`Idempotency-Key`，首次 `202` | 同一次取号的网络重试复用键；相同客户端的重叠取号合并；异常成功响应保留原键 |
| 异步取号 | `creating` 后等待 `assigned` | 查询失败可在等待期限内退避重试；到期后再次调用继续查询原订单 |
| 收码及终态 | `received` 才表示收码；`terminal=true` 停止轮询 | 读取短信中的六位码；矛盾终态及未知状态转人工核查 |
| 人工核查 | `review` 时次数继续冻结 | 停止自动轮询、换号和回收重试；不标为取消或退次 |
| 取消 | `POST /orders/{id}/cancel`；可能返回 `cancel_not_confirmed` | 查询同一个订单核实；只有 `cancelled` 或 `failed` 才生成退次依据，校验回执编号 |
| 限流 | 读写分别限流，`429` 后等待 `Retry-After` 秒 | 创建重试不再将等待截短到五秒；后续同客户端的同类请求遵守退避 |

本次调整集中在既有实现的兼容性缺口：补齐限流等待、异常响应后的幂等保护、异步查询恢复、终态停止处理和 JSON 取消回执。接码池接受经过核对的大西瓜取消回执，并保留服务商退次依据；其他供应商原有 `ACCESS_CANCEL` 回执仍沿用原语义。

本项目仍通过单订单接口查询任务，未新增余额管理、卡密兑换或全账户订单扫描。官方建议并发时使用列表接口属于进一步优化建议，不是已接入路径的强制迁移要求。

验证使用合成数据与本地 HTTP 服务：覆盖超过五秒的限流、非 JSON 限流响应、异步查询暂时失败、超时后的订单复用、重叠取号、异常成功响应、终态冲突、人工核查、取消未确认、回执编号不匹配、回收状态与 CDK 次数隔离，以及 API Key 脱敏。对应测试位于 `test/daxigua-sms.mjs`、`test/daxigua-sms-pool.mjs` 和 `test/sms-provider-console-smoke.mjs`。
