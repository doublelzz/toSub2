# CDK 页面设计

## 任务与边界

这是现有 toSub2 账号工作台的扩展。普通用户关注自己的账号与可用导入次数；管理员关注次数分发、使用流水和异常访问。页面以实际操作为主，不增加营销首页。

本轮先交付可交互原型和实施文档。沿用根目录 DESIGN.md 的视觉身份；不改生产入口，不接真实鉴权，不改变现有 MFA 或账号协议行为。

## 第一遍：设计计划

### 色彩与文字

| 名称 | 色值 | 用途 |
|---|---|---|
| 工作区 | `#f3f5f8` | 长时间操作时的冷灰背景 |
| 表面 | `#ffffff` | 侧栏、表格、输入和抽屉 |
| 正文 | `#202a3b` | 主要内容 |
| 辅助文字 | `#5f6c80` | 说明、时间及表头 |
| 操作蓝 | `#365edb` | 主操作、当前导航及选中 |
| 边界 | `#e1e6ef` | 分隔业务区域 |

成功、警告、危险使用现有语义色 `#1a7353`、`#916015`、`#b4404b`，同时保留文字。深色沿用现有石墨背景及浅蓝操作色，不重新定义品牌。

字体继承 `IBM Plex Sans, Noto Sans SC, Segoe UI, Microsoft YaHei, sans-serif`；本机可用字体决定实际呈现，不声称已打包字体。正文 14px，表单 14px，辅助内容 12px，页面标题 24px，登录标题 34px。表格中的余额及次数右对齐，使用等宽数字；确认区域按等式顺序排列，普通标签不用等宽字体。CDK 字符串属于标识数据，可用现有日志等宽字体栈。

### 结构比较与选择

方案 A 在现有侧栏内增加“我的 CDK / Sub2API / CDK 管理 / 安全中心”，保留授权与 MFA 的位置。方案 B 把 CDK 和安全放入配置抽屉，会把管理员的高频管理工作藏得过深，因此采用 A。无需替换现有工作台外壳。

```text
桌面：
┌─────────────── 设计预览工具（不属于生产页面） ───────────────┐
│ toSub2      │ 工作区 / CDK 管理          当前 CDK / 主题 / 退出 │
│ 账号授权    ├─────────────────────────────────────────────┤
│ MFA 修改   │ CDK 管理                           生成 CDK  │
│ 我的 CDK   │ 状态数量与次数统计（连续信息带）               │
│ Sub2API    │ 搜索 / 状态筛选                               │
│            │ CDK  备注  已用  可用  状态  最近使用  操作     │
│ CDK 管理   │ 逐行查看与追加；详情在右侧抽屉                │
│ 安全中心   │                                             │
└────────────┴─────────────────────────────────────────────┘

确认导入 / 追加 / 融合：
┌───────────────────────────────────────┐
│ 操作名称                         关闭 │
│ 输入或核对来源                        │
│ 当前次数    本次变化    操作后         │
│   48          +100        148          │
│ 影响说明、错误或不可撤销的确认         │
│                           确认操作    │
└───────────────────────────────────────┘

手机：顶部品牌、可换行导航、页面标题与主操作；列表保留标识、
状态和详情入口，次要字段进入详情。所有页面避免横向页面滚动。
```

### 特征与原则

页面的特征是“先看清次数变化，再执行操作”：导入预览给出新增和更新数量；追加和融合用同一条前后余额结构。它只在需要决策的位置出现，不成为每页重复的大数字装饰。

表格、说明和表单左对齐，数字列右对齐。默认一个明确主操作；完整 CDK 只在生成结果中展示一次。普通用户看不到管理入口；原型顶部的身份切换始终标明为预览工具。

## 第二遍：对照业务审查

- 去掉常见的四张统计卡，改成与现有工作台一致的连续统计带，避免把“可用次数”和“现存账号数”误读为同一概念。
- 不引入登录营销海报、装饰渐变或新的品牌字体，维护现有熟悉感。
- 合并入口从账号列表移到“我的 CDK”，因为它处理的是次数账户，不是账号任务。
- Sub2API 位于当前 CDK 导航内，页面明确上传关联与自动修复范围，不用“全局巡检”的说法。
- 将安全日志和 IP 黑名单放在同一安全中心内的两个标签页，管理员可从异常事件直接拉黑来源 IP。
- IP 封禁页取消可提交的登录表单；普通验证失败保留表单并提示重试。合并资格失败与登录错误分开表达。

## 页面与交互规格

| 页面 | 首要动作 | 必须覆盖的状态 |
|---|---|---|
| CDK 登录 | 验证并进入 | 空输入、验证中、统一失败、会话失效、IP 封禁 |
| 账号授权 / MFA | 导入和操作自己的账号 | 新增扣次、更新不扣、跨工作区不扣、零余额、空筛选 |
| 我的 CDK | 查次数 / 融合未使用 CDK | 来源无效、曾扣次、资格通过、最终确认、成功作废源 CDK |
| Sub2API | 保存个人配置 | 未配置、已保存、自动修复关闭 / 开启、关联范围说明 |
| CDK 管理 | 生成 CDK | 筛选空、生成一次性结果、追加次数、禁用 / 启用、详情流水 |
| 安全日志 | 处理异常 / 拉黑 IP | 未读告警、累计失败、已处理、自动封禁、来源已拉黑 |
| IP 黑名单 | 添加 / 解除封禁 | 格式错误、重复 IP、临时 / 永久、解除确认、空列表 |

### 关键约束

- 普通用户初始使用“当前 CDK”范围；管理员账号列表可按 CDK 筛选，同邮箱的不同归属不能合并显示。
- 零余额仍允许打开导入：全部为已有账号时可以更新；包含新账号且余额不足时不能提交，现有任务操作继续可用。
- 导入前展示去重后的新增、已有、错误行、预计扣次和扣后余额。任何错误或不足时整批不写入。
- 融合必须先验证来源，再展示转入次数与源 CDK 失效说明，勾选确认后提交；客户端预览不取代后端提交时重新检查。
- 未知 / 不可用 CDK 的验证提示统一；已通过密钥验证后的融合资格错误可以说明“曾消耗次数”。
- 管理员生成结果关闭后不提供再次查看完整值，详情只显示脱敏标识；禁用、解除封禁有清楚的影响说明。
- 安全告警仅管理员可见，同 IP 同规则的事件聚合显示；普通用户不接触安全事件明细。

## 响应与可访问性

桌面沿用 176px 侧栏和 28px 内容边距。900px 以下侧栏转顶部导航；640px 以下次要表格列隐藏并保留详情入口，表单转单列。支持 320px 宽度，粗指针控件至少 44px。

使用语义表格、真实 label、可见焦点、文字状态及 `aria-live` 操作结果。抽屉 / 确认窗使用原生 dialog，限制焦点、Escape 关闭、关闭后恢复触发控件焦点。跟随系统 / 浅色 / 深色均可选，尊重减少动态效果。正文与辅助文字按实际主题检查对比度。

## 原型数据与生产差异

所有数据均为示例。原型状态驻留内存，下载只包含示例值；角色工具仅帮助设计评审。真实鉴权、密码学密钥生成、会话、事务、数据库、可信代理解析及 IP 执法由后端实施文档约束，不能由前端控件承担。
