## 已确认业务规则

1. 用内部固定 `cdk_id` 与规范化邮箱作为联合主键。同邮箱在不同 CDK 下是两个独立账号，凭据、会话、任务、输出及操作历史分别保存。
2. 普通 CDK 每成功新增一个账号扣一次；同 CDK 的重复导入为更新，账号在授权、MFA、重试、接码和导出之间流转不重复扣次。
3. 次数融合只允许累计从未发生导入扣次的普通源 CDK；转移全部余额后源 CDK 作废，保留审计记录。目标 CDK 可以已消耗过次数。
4. 每个 CDK 独立保存 Sub2API 配置。自动修复为独立可选开关，默认关闭，只处理本 CDK 明确关联的远端账号。
5. 记录 CDK 验证失败，达到阈值向管理员显示站内告警，支持自动临时封禁和手动 IP 黑名单。
6. 首次初始化一个不限次管理员 CDK。历史账号关联管理员，不追扣次数，不分配给首个普通登录者。

## 交付边界

`index.html` 仍是独立原型；实际应用入口为根目录 `npm run dev` / `npm start`，不要把此原型页当作真实服务。业务源码接入保留此前未提交的 MFA 工作及既有全局视觉规范。
