# CDK 系统实施改造文档

日期：2026-10-23。规格基线：用户确认的 CDK 业务方案及后续四项修订。本文是待实施设计，不能视为生产功能已生效。

## 1. 目标与不变量

- 首次初始化一个管理员 CDK；页面先验证 CDK，再进入工作台。
- 普通 CDK 每成功新增一个账号扣一次。授权和 MFA 使用同一个账号登记簿；同 CDK 重复导入为更新，内部流转不扣次。
- 账号主键是 `(cdk_id, normalized_email)`。不同 CDK 的同邮箱是不同的本地业务账号，不读取、覆盖或同步对方的任何数据。
- 源 CDK 从未发生导入扣次才能融合。转出全部余额后永久作废；管理员 CDK 不参与。
- 每个 CDK 拥有自己的 Sub2API、邮件、接码和代理配置，后台操作必须携带明确的 CDK 身份。
- CDK 登录与融合验证共用访问保护；管理员拥有安全日志、站内告警和 IP 黑名单。

以下区分三个数量：累计导入消耗、当前保存账号数、任务成功数。删除账号不退次；重导本 CDK 曾导入的已删除账号为恢复，不再次扣次。普通 CDK 零余额仍可登录、更新和操作已有账号。

## 3. 身份、会话和授权

### 3.1 CDK

`cdk_id` 为内部固定 ID，与完整登录密钥分离。轮换密钥只更新摘要和会话版本，账号归属、余额、流水保持不变。

完整密钥由安全随机数生成器生成至少 192 位随机内容；不使用递增 ID、时间戳或短数字作为秘密。对验证摘要加唯一约束，碰撞重试。普通管理响应只包含脱敏标识和内部 ID。

管理员生成结果只展示一次，可显式复制或下载。后续无法恢复完整密钥；遗失时轮换。创建、轮换、禁用和额度修改记录管理审计。初始化使用本机专用流程，不能把初始化口令暴露在公共 bootstrap、浏览器静态资源或常规日志中。

### 3.2 会话

登录成功后生成服务端随机会话，只把会话 ID 放入 `HttpOnly` Cookie，HTTPS 配置 `Secure`，使用合适的 `SameSite` 并验证 CSRF / 同源请求。完整 CDK 不放在 URL、localStorage 或常规请求日志。

首版会话建议 24 小时绝对有效期、2 小时空闲期限，可配置；刷新不能突破绝对期限。退出只撤销本会话；轮换或禁用撤销该 CDK 的全部会话。所有业务请求重新检查状态及会话版本，不能依赖页面登录时的一次性检查。

公共接口仅为最小 bootstrap、登录和必要健康信息。静态前端可以加载，账号数据、配置、结果文件、日志及管理接口必须经后端门禁。需要检查开发服务器的额外监听端口和文件访问能力；生产入口应提供构建后的静态资源，不把开发中间件当作访问边界。

### 3.3 权限矩阵

| 资源 / 动作 | 普通 CDK | 管理员 |
|---|---|---|
| 账号、任务、日志、输出、原始资料 | 自己 | 全部，保留所属信息 |
| 账号导入 | 自己，扣自己次数 | 默认归管理员，不限次 |
| MFA、会话恢复、后台修复 | 仅自己的账号 | 可操作明确选定的账号 |
| 个人配置 | 读写自己 | 自己；管理查询对其他人的秘密脱敏 |
| 余额、流水 | 自己 | 全部 |
| CDK 生成、追加、禁用、轮换 | 无 | 有 |
| 融合 | 当前登录的普通 CDK 为目标 | 不参与 |
| 安全日志、IP 黑名单、全局上限 | 无 | 有 |

普通请求不得通过提交 `ownerCdkId` 指定身份。资源 owner 来自服务端查询和会话；管理员筛选或代理操作是独立显式管理能力，并记录操作者和目标 CDK。普通用户查询不存在和不属于自己的任务使用相同的 404 结果。

## 4. 数据模型

新增 SQLite 数据库，置于既有持久输出根目录的私有子目录。数据库与恢复材料一起备份。Node 现有运行基线为 20+，实施时选择并验证兼容实际 Windows / Linux 部署环境的 SQLite 驱动，不在设计阶段假设已安装新依赖。

| 表 | 核心字段与约束 |
|---|---|
| `cdks` | `id`、`secret_hash UNIQUE`、脱敏标识、`role`、`status`、`balance CHECK >= 0`、`import_consumed_total`、`ever_import_debited`、会话版本、备注、创建与最近登录时间 |
| `sessions` | 会话摘要、`cdk_id`、CSRF 信息、创建 / 最后访问 / 绝对到期、撤销时间、会话版本 |
| `accounts` | `PRIMARY KEY(cdk_id, normalized_email)`、稳定内部资源 ID、首次登记时间、软删除时间、私有凭据引用、首次计次批次 |
| `task_bindings` | 原任务 ID、`cdk_id`、`normalized_email`、工作区、状态、恢复材料引用；联合外键关联 accounts |
| `import_requests` | `cdk_id`、幂等键、请求摘要、状态、新增数、更新数、扣次量、结果引用；`UNIQUE(cdk_id, idempotency_key)` |
| `quota_ledger` | CDK、事件类型、变化整数、前后余额、导入批次 / 融合 ID、操作者、时间、备注；仅追加 |
| `merge_operations` | 幂等键、源与目标 CDK、转移次数、完成时间；源 CDK 只允许一次成功转出 |
| `cdk_settings` | 按 CDK 保存配置引用和版本；秘密加密 / 系统凭据存储，公共响应脱敏 |
| `sub2api_bindings` | CDK、配置 ID、配置版本 / 远端实例身份、远端账号 ID、本地联合账号；查询禁止跨 CDK |
| `security_events` | 事件类型、规范化来源 IP、入口、不可逆尝试指纹、时间窗口、次数、触发规则、处理状态 |
| `ip_bans` | 规范化 IP、生效与到期、来源、原因、操作者、解除时间；保留审计 |
| `admin_audit` | 创建 / 轮换 / 禁用 / 追加 / 封禁 / 解封 / 修改规则的主体、目标、时间、结果 |
| `outbox` | 已提交但尚未物化或调度的本地操作；按稳定 ID 幂等恢复 |

`import_consumed_total` 只记录累计实际发生的导入扣次；`ever_import_debited` 一旦为真，不因追加、删除、失败重试或系统补偿转回假。融合转出不是导入消耗，融合完成用终态另行禁止复用。

余额核算：初始发放 + 管理员追加 + 融合转入 - 融合转出 - 导入扣次 + 经审计的系统补偿。现存账号数与成功任务数不参与余额计算。

建议索引：任务 `(cdk_id, workspace, created_at, id)`、账号联合主键、流水 `(cdk_id, created_at, id)`、事件 `(ip, window_start, event_type)`、生效封禁查询；SQLite 启用外键，事务等待和锁冲突按受控策略返回可重试结果。

## 5. 完整隔离清单

- 内存索引、去重、锁键：统一稳定账号 ID 或 `(cdk_id, normalized_email)`。
- 授权 / MFA / 添加密码 / 登出所有设备回调：携带来源 CDK，更新前复核联合身份。
- 凭据存储：Windows DPAPI、macOS Keychain 的 account 键加入 CDK / 账号命名空间，保留原系统加密能力；不为新增功能降级成明文。
- 文件：新账号按 `OUTPUT_ROOT/cdk/<cdk_id>/accounts/<resource_id>/...` 定位，服务端从登记簿解析路径，不接受客户端任意文件路径。
- 会话、检查点、MFA 恢复、额度快照、接码订单、原始信息、输出：各归联合账号，不按全局邮箱搜索文件。
- 前端持久偏好：纯主题与密度可以共用，账号配置以非秘密 CDK ID 命名空间保存；服务端秘密不落浏览器长期存储。
- 任务列表、分页 totalAll、统计、selection、导出默认全集及“停止全部”：先限定身份再筛选和分页。
- 客户端切换 / 退出：取消旧请求、清空旧列表与选择，防止旧异步响应写入新工作区。
- 队列并发保留系统上限，增加按 CDK 公平调度，禁止一个用户通过大量入队长时间饿死其他用户。

## 6. 统一导入与扣次

### 6.1 预览

单个添加、授权批量和 MFA 批量都调用同一个导入服务。邮箱规范化沿用当前项目去空格与转小写，不擅自去掉 `+tag` 或邮箱中的点。

预览按当前 CDK 去重，返回原始行数、重复行数、错误行索引、新增、更新、恢复、预计扣次、当前余额及是否可提交。不查询或返回另一 CDK 是否存在同邮箱。预览不持有额度、不启动任务、不修改凭据。

有格式错误或新增余额不足时整批不提交。零余额且全是更新 / 恢复时允许提交。管理员不限次，但仍记录导入批次与账号归属；未经单独实现，不提供普通接口代扣其他 CDK。

### 6.2 正式提交

1. 验证会话、IP、CDK 状态、输入上限及幂等键。服务器计算请求摘要；同一幂等键不同内容返回 409。
2. 使用本 CDK 私有目录准备加密凭据和可恢复操作材料，不覆盖当前生效凭据，不启动外部账号操作。准备失败清理临时材料，不扣次。
3. 开启写事务，重新检查 CDK 状态和联合账号是否存在，重新计算新增数量；不能相信客户端预览价格。并发导入同一联合账号只允许一次首次扣次。
4. 余额不足则回滚整个批次。余额扣减采用带余额条件的原子更新，禁止先读再在事务外写回。
5. 在同一事务中写账号登记、任务绑定、余额、累计消耗、流水、幂等结果及 outbox。提交后才允许进入工作队列。
6. 按 outbox 幂等物化文件和切换凭据引用；准备材料已经持久保存，重启后继续完成。只有物化就绪的任务可开始协议执行。
7. 如果提交响应丢失，重发同一幂等键返回原结果，不再次扣次。外部登录 / 授权 / 接码失败不触发退次。

文件和系统凭据存储不属于 SQLite 事务。实现必须具有准备、提交、恢复三阶段，不能声称数据库事务能回滚外部文件或账号操作。无法恢复的内部存储故障由唯一补偿操作退回额度并审计，`ever_import_debited` 仍保留历史；普通失败、删除和取消不能调用此补偿。

### 6.3 删除与恢复

删除停止该联合账号的本地任务、清理其凭据与私有文件，但保留软删除登记和计次来源。重新导入恢复登记并写入新提供的凭据，不复活已删除的秘密，不扣次。对另一 CDK 的同邮箱不产生影响。

## 7. 次数融合事务

目标仅来自当前已登录普通 CDK。来源完整密钥经验证后，仅返回脱敏标识、可转次数、资格及短期预览令牌，不返回账号、凭据、配置或历史。

提交使用幂等键，在同一写事务中检查源与目标仍启用、均为普通角色、非同一个 ID、源 `ever_import_debited = false` 且累计消耗为 0、有正余额、尚未融合、无正在提交的导入或预占次数。以稳定顺序锁定 / 更新两者，检查结果后转移源全部余额，写双边流水和融合记录，源状态置 `merged` 并撤销会话。

同一个源同时向多个目标融合，只能一个成功；与源导入竞态也只能一个先提交。若导入先扣次，融合资格失效；若融合先完成，导入因源终态失败。刷新和重试不得重复到账。

预览令牌短期有效，提交仍重新检查，不锁死来源供人无限持有。目标可以已使用过。登录、保存配置不影响源资格；曾扣次后余额恢复仍不具备资格。已融合的源不再启用、不追加次数、不轮换为新可用卡。

## 8. 每个 CDK 的 Sub2API

当前巡检的行为是定时查询远端异常账号，为具备全自动登录资料的本地账号重新登录授权，并回写新凭据、清除错误、恢复可调度。它是实际后台任务，不只是服务健康检查。

改为每 CDK 独立配置和状态：服务地址、API Key、分组、上传参数、自动修复开关、检查间隔、冷却、最后结果及下次时间。首版每个 CDK 一组配置，自动修复默认关闭，建议间隔与失败冷却最低 5 分钟；统一调度器管理到期项目，避免每 CDK 各起一个不可控计时器。

上传成功持久化远端账号绑定。自动修复仅操作本 CDK 本实例明确绑定的远端 ID；远端异常列表中未绑定的条目跳过，不因邮箱相同自动认领。不在本地创建新账号，因此不扣导入次数。

任务启动时固定配置版本及远端实例。更换 URL / API Key 后，旧配置的待回写操作暂停并提示，禁止把旧实例的账号 ID 写到新实例。配置撤销、CDK 禁用、会话退出的语义分开：退出登录不停止已授权后台工作；关闭自动修复或禁用 CDK 应阻止新的巡检执行。

部署前验证服务地址及重定向策略，配置的外部目标不能绕过部署的出站边界。API Key 只在必要服务器请求中使用，不进入日志、列表响应和原型数据。管理员可查看运行概况，默认仍将秘密脱敏。

## 9. 防猜测、日志与 IP 黑名单

### 9.1 默认规则

| 设置 | 首版建议默认值 |
|---|---|
| 验证请求频率 | 每 IP 每分钟 30 次，超过返回 429 |
| 失败告警 | 同 IP 10 分钟内失败 5 次 |
| 自动封禁 | 同 IP 10 分钟内失败 10 次，封禁 30 分钟 |
| 重复触发升级 | 24 小时内第 3 次自动封禁，封禁 24 小时 |
| 日志保留 | 30 天；聚合重复拦截，控制写入增长 |
| 手动封禁 | 30 分钟、24 小时或永久，必须有原因 |

阈值是本方案默认值，需能在管理员设置中修改并审计。成功登录不清空整个 IP 的失败窗口。结合全站验证速率和分布式异常告警，避免只按 IP 计数；单个候选密钥的错误不永久锁定真实 CDK。

覆盖登录、融合来源验证及未来任何完整 CDK 验证入口。未知 / 禁用 / 已融合密钥统一返回“CDK 无效或不可用”，对失败响应避免泄漏存在性。来源完整密钥验证通过后，可返回已消耗等明确业务资格错误。

### 9.2 日志与告警

每次验证失败计入聚合事件，事件含入口、首末时间、规范化 IP、不可逆候选指纹、次数和结果。原始 CDK、请求体、Cookie、OTP、密码、MFA、代理秘密及 Sub2API API Key 不写日志。指纹采用独立审计密钥的 HMAC，不能复用登录凭据校验摘要作为公开标识。

失败 5 次产生管理员未读告警，继续累加同窗口事件；封禁与解除保留独立审计。页面提供站内角标、待处理筛选及从事件拉黑 IP 的入口。本轮不增加邮件、即时通讯等外部通知通道。

### 9.3 IP 识别与执行

直连使用 socket 地址。部署在反向代理后，仅当直接对端匹配配置的可信代理集合，才解析指定转发头；按可信链从近到远解析实际客户端，不能接受任意客户端自报的 `X-Forwarded-For`。

统一 IPv4、IPv6 和 IPv4-mapped IPv6 表达，禁止借不同文本表示绕过同一地址的封禁。黑名单针对访问本系统的客户端，和任务出站代理配置无关。

封禁在业务请求入口检查，已登录请求也生效；封 IP 不自动修改账号任务状态。黑名单持久化，计数窗口重启后不得直接清零恢复可攻击状态。提供本机管理命令列出 / 解除封禁，保留审计，避免管理员误封后无法恢复。

IP 封禁页不暴露 CDK 是否有效；显示访问限制和恢复方式。健康检查仅返回最小健康状态，不返回账号、配置及初始化秘密。

## 10. 接口草案

所有管理接口服务端校验管理员角色；所有普通接口按当前会话限域。所有写操作验证同源 / CSRF。下表为新增或替换设计，尚未存在。

| 方法与路径 | 含义 |
|---|---|
| `POST /api/auth/login` | 验证 CDK，设置会话；失败计数 |
| `GET /api/auth/me` | 当前身份、角色、脱敏标识、余额和能力 |
| `POST /api/auth/logout` | 撤销当前会话 |
| `GET /api/cdk/ledger` | 当前 CDK 流水，分页 |
| `POST /api/cdk/merge-preview` | 验证来源，返回融合资格和预览 |
| `POST /api/cdk/merge` | 幂等提交融合，重新检查资格 |
| `POST /api/imports/preview` | 共用导入预览，指定授权或 MFA 工作区 |
| `POST /api/imports` | 幂等导入、扣次并登记后续调度 |
| `GET/PUT /api/settings/sub2api` | 当前 CDK 的脱敏配置读取 / 更新 |
| `POST /api/sub2api/monitor/check` | 本 CDK 手动触发已启用的修复检查 |
| `GET/POST /api/admin/cdks` | 管理列表 / 批量生成 |
| `POST /api/admin/cdks/:id/topups` | 幂等追加正整数次数，强制备注 |
| `PATCH /api/admin/cdks/:id` | 备注、禁用 / 启用；已融合为终态 |
| `POST /api/admin/cdks/:id/rotate` | 轮换密钥、一次性显示、撤销会话 |
| `GET /api/admin/cdks/:id/ledger` | 具体 CDK 用量流水 |
| `GET/PATCH /api/admin/security/events` | 分页事件与处理状态 |
| `GET/POST /api/admin/security/ip-bans` | 生效 / 历史封禁查询、手动拉黑 |
| `POST /api/admin/security/ip-bans/:id/revoke` | 幂等解除并记录原因 |
| `GET/PUT /api/admin/security/rules` | 访问限制阈值读取 / 修改与审计 |

现有任务、批量、MFA、日志、下载、导出和配置接口保持业务能力，但必须接入统一会话与资源校验。列表、日志及错误消息不能夹带其他 CDK 的计数或邮箱。

状态码建议：401 会话缺失 / 失效，403 角色禁止或访问封禁，404 不存在 / 无权查看的资源，409 幂等冲突 / 状态变化 / 余额不足，422 输入错误，429 请求频率限制。登录失败的业务提示保持统一。

## 11. 初始化、迁移与部署

1. 停止接收新增导入，检查活动任务；等待或在安全检查点保存，备份输出、系统凭据引用和监控配置。
2. 本机初始化 CDK 数据库与管理员身份；初始化秘密只通过专用安全渠道领取一次。数据库丢失但已有任务数据时进入恢复流程，不能静默当新安装生成另一管理员。
3. 以管理员身份登记既有授权和 MFA 账号，同邮箱关联到同一管理员账号但保留工作区记录。不追扣，不推断原始密码归属，不暴露给首个普通登录者。
4. 建立旧凭据到管理员命名空间的迁移映射，验证可读后切换引用；升级时不可在未备份情况下删除唯一旧凭据。
5. 未能明确关联或损坏的历史记录进入管理员待处理集合，禁止无 owner 数据默认对所有 CDK 可见。
6. 旧 Sub2API、邮件和接码服务端配置归管理员；浏览器旧配置不得自动发送到新普通 CDK。旧全局自动修复先暂停，由管理员确认绑定后恢复。
7. 迁移使用版本与检查点，重复执行不重复创建管理员、不重复登记、不扣次数；旧未认证客户端停止工作。
8. 验证后开放新入口，再分发普通 CDK。部署保留现有输出目录、凭据能力、网络和任务恢复材料。

回滚必须备份数据库与文件同一业务检查点。新系统一旦写入多个 CDK 数据，旧无身份版本不能直接接管新输出根目录；回滚需使用升级前快照或保持停机只读，不能退回公共访问模式暴露新用户数据。

禁用 CDK 后立即阻止新请求、导入、队列启动和巡检；正在进行的 MFA 等关键操作先保存恢复点、到安全节点暂停，不直接杀死无法恢复的步骤。额度为零不等同禁用。退出登录不停止后台任务。
