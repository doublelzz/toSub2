## 首次启动

运行环境为 Node.js 22.13.0 或以上，SQLite 使用 Node 内置模块，无新增数据库原生扩展依赖。

```bash
npm install
npm run dev
```

启动自动构建前端并初始化管理员身份，默认监听 `127.0.0.1:4399`。在相同系统用户下另开终端，领取一次管理员 CDK：

```bash
node src/cdk-admin.mjs initial
```

常规服务日志和公共 bootstrap 不展示完整 CDK。领取完成后该初始化结果被删除；管理员初始化、普通 CDK 生成、轮换和成功登录时，会另行使用应用 vault 加密保存可查看的完整值。已登录用户通过带 CSRF 的 `POST /api/cdk/reveal` 查看当前服务端工作区的 CDK，不能通过提交其他 ID 越权读取；响应禁止缓存，审计不含完整值。旧版本仅存摘要且没有可迁移初始化结果时，返回 `CDK_SECRET_UNAVAILABLE`，可重新登录或在查看面板验证当前 CDK 后补存。无法重新验证的管理员可在本机执行 `node src/cdk-admin.mjs rotate-admin`，旧管理员密钥和会话会失效。

指定 `ONBOARDING_OUTPUT_ROOT` 时，服务与管理命令必须使用同一值。Windows / macOS 用系统凭据保护应用加密密钥；Linux 需要配置持久的 `TOSUB2_ENCRYPTION_KEY`，值为 32 字节随机内容的 Base64。数据库、原系统加密密钥及输出资料需要配套备份，不能删除数据库后让旧账号自动重新初始化。

`TOSUB2_ADMIN_CDK` 是可选的首次初始化密钥输入，至少 24 字符；不是每次启动重置管理员的开关。协议子进程不会继承它或应用加密密钥。

PM2 部署前运行 `npm run build`。本次没有重启或替换真实数据目录中的服务。

## 历史资料与配置迁移

- 原输出根目录继续作为初始化管理员工作区，授权和 MFA 同邮箱归同一管理员账号，不追扣历史次数。
- 普通 CDK 放入 `OUTPUT_ROOT/cdk/<cdk_id>`，不会扫描其他 CDK 的子目录。旧按邮箱存储的凭据仅由管理员的已知历史账号读取并迁入独立命名空间，普通用户无回退权限。
- CDK 数据库与私有加密设置位于 `OUTPUT_ROOT/.cdk`。原登录流程仍使用 Windows DPAPI / macOS Keychain 的既有凭据能力；Linux 原本不持久保存账号密码的限制保留。
- 旧浏览器配置只在管理员自己的首次空配置工作区迁移；成功保存后移除对应旧值，普通 CDK 不继承。主题和列表密度仍可作为本浏览器偏好。
- 原全局 Sub2API 监控配置归管理员并暂停；原配置文件替换为迁移标记，密钥存入加密设置。确认远端账号关联后再启用自动修复。
- 删除授权记录后，若同邮箱仍存在于 MFA 工作区，统一账号登记仍保持有效；完全删除后保留计次墓碑，重新导入不再次扣次，但需要重新提供凭据。

## Sub2API 关联与配置变化

上传会给远端记录附加当前 CDK 和配置指纹。响应能明确给出远端 ID 时立即保存关联；响应没有明确 ID 时，后续读取到匹配附加标识才能采用。已经存在的远端账号可从配置抽屉的“关联已有远端账号”入口填写本地邮箱及远端 ID，服务器核对后绑定。

配置身份包含当前 CDK、完整规范化配置的加密指纹和持久配置版本。相同 URL 更换 API Key、甚至 A → B → A 换回原 Key，都不会让旧待回写 ID 自动复活。重试及实际 PUT 前检查配置仍启用、明确绑定仍成立、远端邮箱仍匹配；配置变更同时终止旧的进行中请求。

旧配置的待回写记录保留用于排查，不能自动写到新配置；管理员需要明确重新核对关联。外部调用已经发出的结果不能回滚，本地避免在检测到配置变化后继续后续步骤。

## 访问保护与本机恢复

默认：每 IP 每分钟验证 30 次；10 分钟内失败 5 次告警、10 次封禁 30 分钟；24 小时内第 3 次触发升级为 24 小时。管理员可修改规则，日志默认保留 30 天。登录和融合来源验证共用计数，成功验证不清空失败窗口。

黑名单针对访问本系统的客户端，包含已登录请求，和账号任务使用的出站代理无关。`TOSUB2_TRUSTED_PROXIES` 使用逗号分隔的明确可信代理 IP；未配置时不接受客户端自报的转发来源。反向代理的公开来源可用 `TOSUB2_PUBLIC_ORIGIN` 指定。

```bash
node src/cdk-admin.mjs bans
node src/cdk-admin.mjs unban 198.51.100.10
```

本机解除也写审计。完整 CDK、Cookie、加密主密钥和提交的账号资料不写验证失败日志；错误尝试使用独立不可逆指纹。

## 设计与当前实现的差异

- 沿用每 CDK 的独立词法工作区封装原任务流程，工作区内原任务元数据仍是文件；SQLite 统一记录身份、账号登记、计次、配置和安全，未把所有协议任务状态迁为数据库列。
- 扣次采用“事务预留 + 加密待处理材料 + 暂停工作区写入 + 事务确认”的恢复流程。进程中断保留原请求和预留，工作区恢复完成前禁止新导入；不以失败自动重新发额度。
- 暂存和系统凭据不属于 SQLite 事务。可恢复错误保留原请求，在管理员页面恢复；无法读取系统密钥或底层存储时，需要先恢复存储条件，不会自动猜测并补偿。
- 同数据目录使用进程锁，禁止同时启动多个服务实例；不是支持共享同一目录的多节点部署方案。
- 管理页及流水当前有受控返回上限，尚未增加历史账单归档、复杂统计图或对外通知渠道。
